The Stage 3 aggregation report records:
- 4,318 MethodDef linked-call rows.
- 8,109 joined rows.
- 4,335 unique callsite keys.
- 17 duplicate callsite keys / join-multiplicity cases.
- Large multiplicity examples include a blank caller identity for
  Assembly-CSharp.dll matching 360 declarations and other broad matches.

This is a material audit warning: the aggregation output contains join
multiplicity that can inflate or ambiguously associate declarations. The
fixed scanner's code uses assembly identity + declaring type + method name +
raw signature bytes for MemberRef/MethodSpec P/Invoke association and labels
ambiguous matches rather than silently choosing one. However, the supplied
aggregation report has not been proven to have been generated by that exact
fixed scanner revision. The two outputs must be reconciled before treating
all aggregated call links as exact.

The fixed scanner also declares fatal validation counters for file errors,
method-body parse errors, ImplMap resolution errors, P/Invoke flag errors,
missing ImplMap rows, orphan ImplMap rows and duplicate method rows. Its
script was syntax-inspected only; it was not run because the managed DLL
payload directory is not included in these two ZIPs.

============================================================
6. CONCRETE REPRODUCIBLE DEFECT FOUND
============================================================

Both token resolver scripts contain a report-writing expression equivalent to:
    f.write("\\n".join(lines) + "\\n")

That writes literal backslash+n characters instead of newline characters.
The archived token report files confirm this formatting defect: the main
fourier_gpu_token_report.txt and ceto/fourier_support_token_report.txt have
zero actual LF bytes and many literal \\n sequences. The resolved IL output
is written separately from the original source string, so this particular
bug affects the human-readable token report formatting, not the IL token
replacement operation itself.

No source files were modified during this audit. This is recorded as a
contained reporting defect to fix later, after confirming the canonical
script copy in the full research world.

============================================================

Some archived Ceto scripts hard-code the original game path as:

The user's current stated original-game path is:
Download/Stranded Deep

The archive scripts therefore appear to refer to an earlier folder layout.
Before rerunning any extractor, reconcile its configured ROOT/DLL paths with
the actual current path. The scripts also write to relative output folders
such as output/ and logic/; do not execute them in the live research world
until output targets and overwrite behavior are reviewed.
